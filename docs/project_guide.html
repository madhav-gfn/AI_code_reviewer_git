Overview

What is mygit?

🎯 The Problem

Code reviews are essential but often delayed. Cloud-based AI reviewers raise privacy concerns and depend on API keys, network access, and monthly subscriptions. Shell-based git integrations are brittle. LLM outputs are notoriously unreliable — random markdown, trailing commas, hallucinated JSON.

✅ The Solution

mygit runs a local GGUF language model via llama.cpp, interfaces with Git natively through libgit2 (no shell commands), and uses GBNF grammars at the sampling layer to mathematically force the model to output valid JSON. Zero parsing errors. Ever.

Features

Key Features & Innovations

Every feature is designed for speed, privacy, and reliability.

🧠

Local AI Inference

Runs .gguf models entirely on your hardware via llama.cpp. Seamlessly offloads to GPU (CUDA/Vulkan) or falls back to optimized CPU. No cloud, no API keys, no network calls.

llama.cpp GGUF CUDA
📐

Grammar-Constrained JSON (GBNF)

Uses GGML BNF grammars at the sampling layer to mathematically guarantee the model outputs valid JSON. Zero parsing errors — the model is physically incapable of generating malformed output.

GBNF Deterministic
⚖️

Decision Engine & Verdicts

Parses AI feedback into structured severities (Critical, High, Medium, Low). Critical issues block commits/pushes automatically. Developers can override with --force-ai.

Severity Levels Blocking
💬

Auto Commit Messages

Generates Conventional Commit messages from your diff (e.g. feat(auth): add JWT validation). Interactive flow: accept, edit in $EDITOR, or fall back to standard git.

Conventional Commits Interactive
🔗

Native Git (libgit2)

No shell-outs or brittle popen() calls. Directly traverses the Git object database via libgit2's C API. All C pointers wrapped in RAII unique_ptr with custom deleters.

libgit2 RAII Zero Leaks
🧬

RAG Pipeline

Retrieves semantically related code from your repo and feeds it into prompts. Tree-sitter AST parsing, BPE tokenizer, ONNX embedding model, and FAISS vector search — all running locally.

ONNX Runtime FAISS Tree-sitter
💾

SQLite Review Memory

Every verdict persisted to a local SQLite DB with ACID transactions. Prepared statements prevent SQL injection. Async background writer keeps the CLI responsive.

SQLite3 ACID Async
👻

Daemon Architecture

Background HTTP daemon keeps the model loaded in VRAM persistently. CLI sends lightweight HTTP requests. Zero cold-start penalty. Auto-shutdown after 15 min idle.

cpp-httplib Localhost IPC
🎨

Rich Terminal UI

FTXUI-powered colored reports, animated spinners, boxed review cards, and a beautiful history table. Severity-coded badges for every issue.

FTXUI ANSI Colors

Deep Dive

Module Deep Dive

Every module explained — what it does, how it works, and why it exists.

AI Engine   ai/ — LlamaClient, PromptBuilder, ReviewAggregator ▼

LlamaClient (ai/llama_client.cpp/.h) — The heart of the AI subsystem. Loads a GGUF model once and holds it in memory. Key features:

  • GBNF Grammar Enforcement: Applies a BNF grammar at the sampling layer, making the model physically incapable of generating anything other than the expected JSON schema.
  • Prefix KV Caching: The system prompt + grammar instructions are cached in the KV cache. Subsequent calls with the same prefix skip re-evaluation entirely — only the diff suffix is processed.
  • Split Prompt API: review(SplitPrompt) and generate_commit_message(SplitPrompt) separate the static prefix from dynamic suffix for caching.
  • GPU Offloading: Configurable n_gpu_layers — set to 99 to offload the entire model to GPU.

PromptBuilder (ai/prompt_builder.cpp/.h) — Constructs all prompts. Supports plain, context-aware (RAG), and split (KV-cacheable) variants for both reviews and commit messages.

ReviewAggregator (ai/review_aggregator.cpp/.h) — Merges per-file review results into a single repository-level result. Used in batched per-file processing mode.

Git Layer   git/ — GitDiff, GitStatus, GitRunner ▼

GitDiff (git/git_diff.cpp/.h) — Extracts staged changes using libgit2's C API directly (no shell). Two main methods:

  • get_staged_diff() — Returns the full unified diff as a string.
  • get_staged_file_diffs() — Returns per-file FileDiff objects with rename detection (git_diff_find_similar), binary flags, and content-change metadata.

GitStatus — Queries branch name and staged state via libgit2. All libgit2 pointers use RAII unique_ptr with custom deleters.

GitRunner — Legacy subprocess wrapper for operations not yet migrated to libgit2 (e.g., git commit, git push, git ls-files).

RAG Pipeline   rag/ — CodeParser, Embedder, VectorStore, Orchestrator ▼

The RAG (Retrieval-Augmented Generation) pipeline gives the AI context about your entire codebase, not just the diff.

  • CodeParser — Uses Tree-sitter to parse source files into logical CodeUnits (functions, methods, classes). Supports C/C++, Python, JavaScript, TypeScript, Go, Rust, Java. Non-code files get sliding-window text chunks (~40 lines, 10-line overlap).
  • BpeTokenizer — Byte-level BPE tokenizer loading from HuggingFace tokenizer.json. Exact for ASCII source code; byte-level fallback for non-ASCII.
  • Embedder — Runs an ONNX embedding model (e.g., Qodo-Embed-1-1.5B) via ONNX Runtime. Returns mean-pooled, L2-normalized vectors. Supports CPU and optional CUDA acceleration.
  • VectorStore — FAISS IndexHNSWFlat for nearest-neighbor search. SQLite metadata maps FAISS IDs back to CodeUnits. Supports incremental indexing (per-file content hashes), tombstoning, and lazy rebuilds.
  • RagOrchestrator — Ties everything together. update_index() incrementally re-indexes changed files. get_context_for_diff() embeds the patch and retrieves top-k relevant code units.

Graceful Fallback: If models/tokenizer aren't present, available() returns false and everything degrades to zero-RAG mode silently. Never throws.

Decision Engine   decision_engine/ — Verdict Logic ▼

DecisionEngine::should_allow(result, force_ai) — The gatekeeper. Simple, critical logic:

  • Scans all issues in the ReviewResult
  • If any issue has Severity::Critical → blocks the operation
  • If force_ai == true (via --force-ai flag) → overrides the block
  • All other severities (High, Medium, Low) are reported but never block
Diff Filter   diff_filter/ — Input Preprocessing ▼

Guards against sending garbage or oversized input to the model. Configurable thresholds:

  • max_total_diff_bytes: 50,000 — Rejects entire diff if total exceeds this
  • max_per_file_bytes: 20,000 — Skips individual files exceeding this
  • max_file_count: 30 — Rejects if too many files changed
  • Binary filtering: Automatically skips binary files
  • Rename filtering: Skips pure renames (no content changes) — prevents the AI from analyzing entire file contents for a simple move

Returns a FilteredDiff with the cleaned patch, list of skipped files with reasons, and kept FileDiff objects for per-file batching.

Database   database/ — SQLiteManager & AsyncDbWriter ▼

SqliteManager — RAII wrapper around SQLite3. Manages:

  • Schema: reviews table (id, timestamp, branch, commit_hash, files_changed, blocked, repo_name) + issues table (severity, file, line, message)
  • Prepared Statements: All queries use parameter binding (sqlite3_bind) — zero SQL injection risk
  • ACID Transactions: Review + issues inserted atomically within BEGIN/COMMIT
  • Schema Migration: Auto-adds repo_name column to existing databases
  • Review Cache: Content-hash-based cache for per-file reviews to skip re-inference on unchanged diffs

AsyncDbWriter — Fire-and-forget background thread. Decouples database writes from the CLI's critical path so the terminal returns instantly after inference completes. Uses mutex + condition_variable + FIFO queue. Destructor joins the thread and flushes pending writes.

Daemon   daemon/ — Server, Client, Config ▼

Solves the cold-start penalty problem by keeping the model loaded persistently.

  • DaemonServer: Binds to 127.0.0.1:49352. Exposes /review, /commit, /health, /shutdown HTTP endpoints. Holds a LlamaClient instance that stays alive across all requests. Auto-shuts down after 15 minutes idle.
  • DaemonClient: Thin HTTP client that mirrors LlamaClient's API. Supports split-prompt form for KV cache reuse across CLI invocations. ensure_running() auto-spawns a daemon if none is reachable.
  • spawn_detached_daemon(): Creates a fully detached background process (no console window). Uses Windows CreateProcessW / POSIX fork+exec.
UI & Logging   ui/, logger/, reports/ ▼
  • terminal_ui.cpp: FTXUI-based rich terminal output. Animated spinner during inference (background thread). Colored severity badges (🔴 Critical, 🟠 High, 🟡 Medium, 🔵 Low). Boxed review report card. Verdict line with ✓/✗/⚠ symbols.
  • review_logger.cpp: spdlog rotating file sink writing to ~/.mygit/logs/mygit.log. Max 5MB per file, 3 rotated files. Logs timestamp, command, severity counts, blocked status, inference time.
  • report_generator.cpp: Simpler stdout renderer (fallback for non-FTXUI environments).
Design

Key Design Decisions & Reasoning

Why specific architectural choices were made.

1

libgit2 Over Shell Commands

The original implementation used popen("git diff --staged") which proved incredibly brittle across operating systems — different newline handling, locale-dependent output, PATH requirements. Embedding libgit2 directly gives in-memory access to the Git object database without any subprocess overhead. All C-style pointers are wrapped in std::unique_ptr with custom deleters for guaranteed zero memory leaks.

2

GBNF Grammar Constraints Over Prompt Engineering

Asking an LLM to "return JSON" via prompt engineering is unreliable — you get random markdown blocks, trailing commas, or complete hallucinations. GBNF grammars operate at the sampling layer, mathematically constraining which tokens can be generated at each step. The model literally cannot produce anything other than the expected JSON schema. This eliminates the entire class of "parsing error" bugs.

3

Pimpl Pattern for Header Hygiene

Heavy headers like onnxruntime_cxx_api.h, llama.h, tree_sitter/api.h, httplib.h, and sqlite3.h are kept strictly out of public headers using the Pimpl (Pointer-to-Implementation) idiom. Only the .cpp files pay the compile-time cost. This keeps compile times low and prevents transitive dependency leaks.

4

Graceful Fallback Architecture

Every optional subsystem (RAG pipeline, daemon, ONNX CUDA) follows the same pattern: construction never throws, available() returns false if resources are missing, and all methods become safe no-ops. This means mygit commit works immediately out of the box with zero setup, and features activate incrementally as the user provides model files.

5

Daemon Architecture for Zero Cold Starts

Loading a language model takes seconds — unacceptable when the user runs review then immediately commit. The daemon pattern keeps the model in VRAM persistently. The CLI sends lightweight HTTP requests to localhost:49352. Split-prompt KV caching works across CLI invocations since the daemon outlives any single process.

6

Async Database Writes

Blocking the main thread for SQLite I/O while the user waits is bad UX. AsyncDbWriter uses a background thread with a mutex + condition variable + FIFO queue so the CLI returns the instant inference finishes. The destructor joins the thread and flushes, guaranteeing no data loss even on abrupt shutdown.

7

Tree-sitter for AST-Level Chunking

Whole-file embeddings dilute semantic relevance. By parsing files into AST-level CodeUnits (individual functions, methods, classes), each embedding represents a focused, self-contained piece of logic. FAISS retrieval then returns exactly the relevant function, not a 500-line file where 3 lines matter.

8

Per-Repo RAG Isolation

RAG index (rag.index) and metadata (rag.db) are stored inside each repository's .git/mygit/ directory — never globally. This prevents cross-repo embedding clashes. Heavy ONNX model weights stay in ~/.mygit/models/ (shared) to save disk space.

Patterns

Design Patterns Used

🏗️ RAII Everywhere

Every resource — libgit2 handles, SQLite connections, llama contexts, ONNX sessions — wrapped in unique_ptr with custom deleters. No manual free() or close() calls anywhere.

🫣 Pimpl Idiom

Heavy implementation headers (llama.h, onnxruntime, tree_sitter, httplib, sqlite3) hidden behind struct Impl pointers. Only .cpp files pay the include cost.

🔌 Strategy Pattern

CLI commands dispatch through DaemonClient or direct LlamaClient transparently — same API surface for both code paths.

📦 Producer-Consumer

AsyncDbWriter uses a classic mutex + CV + queue pattern. Main thread produces work items; background thread consumes them asynchronously.

🎭 Facade Pattern

RagOrchestrator is a facade over CodeParser + Embedder + VectorStore. Callers interact with one clean interface.

⚡ Graceful Degradation

Optional features (RAG, daemon, CUDA) degrade silently when unavailable. available() check → no-op fallback → zero crashes.

Security

Safety & Privacy Guarantees

🔒 100% Local Inference

All AI inference runs on your hardware. No API keys, no cloud calls, no data leaves your machine. Your proprietary code stays private.

🛡️ SQL Injection Prevention

Every database query uses prepared statements with sqlite3_bind parameter binding. User input is never interpolated into SQL strings.

🧱 Memory Safety (RAII)

All C-style resource handles are wrapped in RAII smart pointers. Zero manual memory management = zero leaks, zero double-frees.

📐 Grammar-Enforced Output

GBNF grammar constraint makes parsing failures mathematically impossible. The decision engine always receives well-formed data.

Setup

Build & Setup Guide

Prerequisites

  • Compiler: C++20 (MSVC 19.3+, GCC 13+, Clang 17+)
  • Build System: CMake 3.21+ & Ninja
  • Package Manager: vcpkg (bootstrapped)
  • Model: Any GGUF model (recommended: Qwen2.5-Coder-1.5B-Instruct)

Build Commands

# Clone the repository
git clone <repo-url>
cd AI_code_reviewer_git

# Configure (vcpkg auto-fetches all deps)
cmake --preset default

# Build
cmake --build build/default

# Configure model
.\build\default\mygit.exe setup

# Install to PATH
.\build\default\mygit.exe install
